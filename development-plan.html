Technology

What we use and why

Everything here is free for a hackathon project.

LayerChoiceWhy
FrameworkNext.js (App Router), React, TypeScript strictVercel's native framework, so deploys need no configuration. Pages, API routes and builds in one tool.
StylingTailwind CSSFast, consistent styling without a stylesheet per component.
ChartsApache EChartsHeatmap and line charts, and it exports a chart as an image, which the challenge asks for.
MapMapLibre GL JS with OpenFreeMap tilesNo token or account needed.
Drawingterra-drawPolygon and rectangle drawing made for MapLibre.
GeometryTurf.js, one functionDecides which map squares lie inside a drawn region.
Data storageStatic JSON files, one per countryThe corrected record is small and read-only. No database needed.
BackendOne Next.js route, /api/recentOnly to keep the NASA key secret when calling the daily feed.
ML and pipelinePython, pandas, scikit-learn, run offlineTraining happens once on a laptop. The app only reads results, so nothing can fail at demo time.
NASA dataFIRMS country files and FIRMS daily feedThe dataset the challenge names. The feed needs a free key.

HostingVercel Hobby plan, root directory webPublic link, a preview build per branch, production build on main.

Not used, on purpose: a database, user accounts, a model server, a state library. Nothing is private and the data is read-only. Each of these would cost hours without adding anything a judge can see.

Three rules that keep it clean

  • Calculations live in web/src/lib/ as plain functions with no React in them.
  • Components only draw and handle clicks.
  • The NASA key is read only inside the server route and is never sent to the browser.

How we work

One step at a time

  1. Build the current step only.
  2. Check it with the validation listed for that step.
  3. Understand it. Everyone on the team can explain what it does.
  4. Commit when the team says so, with the suggested message.
  5. Record it in the step log: what we built, why, how, the result of each check, and anything the next person should know.
  6. Only then start the next step.

Steps 1 to 3 go in order and are built. After step 3 the work splits: the two front-end people share steps 4 to 12, the data person takes step 13, the AI person step 14, and the story person starts step 16 right away.

Step 1 · Front end · Committed

Scaffold the Next.js app in web/

What
An empty Next.js 16.4.6 application in web/, with React 19, TypeScript in strict mode, Tailwind 4, ESLint, the App Router and a src/ folder. No features.
Why
Every later step lives inside it. Doing it alone first means that when something breaks later, we know the base was sound.
How
From the repo root: 
npx create-next-app@latest web --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --disable-git
cd web
npm install
--disable-git stops the tool from creating a second git repository inside ours.
Result
  • npm run lint: no problems.
  • npm run build: compiled, the start page is built as a static page.
  • npx tsc --noEmit: no type errors.
  • npm run dev: the start page answers on localhost:3000.
  • web/tsconfig.json contains "strict": true. There is no web/.git. node_modules and .next are ignored by git.
Good to know
  • After cloning or pulling, run npm install inside web/ before npm run dev. node_modules is not in git.
  • Edits to src/app/globals.css do not show up in a running dev server. Stop it with Ctrl+C and run npm run dev again. Edits to .tsx files, including new Tailwind classes, show up at once. The production build is not affected.
  • Cache Components is switched on in web/next.config.ts. The tool does this by default. It does not matter for static pages. It changes how server-side data loading behaves, so check it again in step 13.
  • web/AGENTS.md is created by Next.js and recreated by npm run dev if deleted. It tells AI coding tools to read the Next.js documentation shipped in node_modules/next/dist/docs/, because this version differs from older ones. We keep it in git.
  • npm audit lists 7 moderate issues. All are in the lint tooling, which never reaches users. Left alone.
Understanding
  • Why a web/ subfolder: the repo holds two separate things, the Python pipeline and the web app. Vercel is told to build only web/.
  • App Router: each folder under src/app/ is a page address. page.tsx is the page, layout.tsx wraps all pages.
  • Server and client components: by default a component runs on the server and sends HTML. Anything interactive needs "use client" at the top of its file.
  • Strict TypeScript: the compiler refuses values that might be missing. It prevents the "undefined" errors that break demos.
  • npm run build: this is what Vercel runs. If it passes locally, the deploy almost always passes too.
  • package-lock.json: pins the exact version of every library, so all five laptops and Vercel install the same thing. It is committed.
Commit
Add Next.js app scaffold in web/

Step 3 · Front end · Committed

Data contract, data files and loader

What
The data is now inside the web app, with a description of its format in TypeScript, a function that loads one country, and a temporary menu that proves it works.
Why
This is the contract between the pipeline and the app. Every number on screen will be read through it, so the format is written down once and checked when a file is loaded.
How
  • web/scripts/copy-data.mjs, run with npm run copy-data inside web/. It copies the 16 country files and report.json from data/out/ into web/public/data/, checks that every row holds 10 numbers, and writes index.json with the country list, row counts and the first and last year.
  • web/src/lib/types.ts: CellRow describes one row. COL gives the position of each value by name. VIIRS_FIRST_YEAR is 2012.
  • web/src/lib/data.ts: loadCountryCells downloads one country file, checks its format and remembers it, so going back to a country does not download it again.
  • web/src/hooks/useCountryData.ts: gives a component one of four states: idle, loading, ready with the rows, or error with a message.
  • web/src/components/DataCheck.tsx: the temporary menu. Step 5 replaces it.
  • The root .gitignore said data/, which also hid web/public/data/ from git. It now says /data/, which only covers the pipeline folder.
Result
  • npm run copy-data: 16 countries, 502,310 rows, 2001 to 2025.
  • npm run lint, npm run build and npx tsc --noEmit pass.
  • In a browser, on the production build: Germany shows 23,292 rows, Ukraine 140,342, Czech Republic 4,304. These equal the row counts of the pipeline files.
  • The test entry for a missing file shows: The data file "Atlantis.json" was not found.
  • Choosing two countries quickly, one after the other, ends on the second one.
  • Not tested yet: the message for a file with a wrong format. It gets a unit test in step 4.
Good to know
  • After the pipeline is rerun, run npm run copy-data and commit web/public/data/. The deployed site only has the data that is in git.
  • Read rows by name, not by number: row[COL.year], not row[2].
  • A viirsRaw of 0 before 2012 means "no data", not "no fire". The newer sensor did not exist yet.
  • The record starts in 2001, not 2000. That is 25 years, 2001 to 2025.
  • Size: web/public/data/ adds 27 MB to the repository. Ukraine is the largest file, 7 MB on disk and about 1.5 MB when sent compressed. It will take a moment on mobile data.
Understanding
  • The public folder: files in web/public/ are served as they are. public/data/cells/Germany.json is reachable at /data/cells/Germany.json.
  • Why one file per country: all countries together are 23 MB. The browser only downloads the one that is chosen.
  • Types as a contract: CellRow tells the compiler what a row looks like. A file is still checked when it is loaded, because the compiler cannot see the contents of a downloaded file.
  • Hook: a function whose name starts with use and that keeps state for a component. useCountryData hides the downloading, so a component only asks "what is the state now?".
  • "use client": the menu reacts to clicks and downloads data in the browser, so its file starts with "use client". The page around it is still built on the server.
  • Cancelling: when another country is chosen, the download that is still running is cancelled. Without this, a slow file could arrive late and overwrite the newer choice.

Deployment

Vercel, before submission

The team decided on Saturday to build first and deploy at the end, as part of step 16. Until then npm run build is our check: it is the same command Vercel runs.

Do not leave it to the last hour. A first deploy often needs one fix, for example a setting or a secret that is missing. Plan it for Sunday morning, so there is time before the 16:00 deadline.

  1. The repository must be reachable by the Vercel account. On the free plan, connect it with the repository owner's account.
  2. In Vercel choose New Project, import the repository and set Root Directory to web. The framework is detected as Next.js.
  3. Secrets are set in Vercel under Settings, Environment Variables. Locally they go in web/.env.local, which is never committed.
  4. Every push to main builds production. Every other branch gets its own preview link. A preview link may ask for a Vercel login. The production link is public.
  5. Test each deploy in a private window and on a phone.
